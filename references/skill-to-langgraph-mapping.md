# 从源语义选择结构

本文在提取源契约和选择结构时读取，给出主文件规则的应用例子。

| 源行为 | 可选实现 | 需要核对的观察 |
| --- | --- | --- |
| 校验输入，再生成文件 | 固定校验节点→文件节点 | 无效输入不能写文件 |
| 自主分析和使用工具 | 直接导出 create_agent 的图 | 任务上下文、工具选择及失败语义保持 |
| 检查输入、自主检索、确认、写报告 | StateGraph 中连接 agent 子图、确认节点、写节点 | 检索自主性和确认前无写入同时成立 |
| 证据不足时继续检索 | 模型判断并选择检索或结束 | 不能用检索次数冒充充分性 |
| 按输入顺序逐项处理 | 默认顺序循环 | 输出、错误及副作用与原项目对应 |
| 源明确许可独立任务并行 | Send 或并行边加适当 reducer | 完成顺序不能打乱约定的汇总顺序 |

例如“确认、写报告”在一段里出现，仍对应暂停与副作用两个边界；段落编号本身无法解释恢复行为。

## 职责与运行上下文

以一份含计划、摘要、评分和引文分析的 Skill 为例，转换 Agent 先阅读完整源包，再形成这样的分配：

| 源义务 | 执行者和输入 | 实现及可观察结果 |
| --- | --- | --- |
| 先计划后摘要 | 图路由；当前阶段 | 摘要执行前已有正式计划 |
| 按指定语言写报告 | 摘要/引文节点及引文批次代理；实际 language 值 | 正文遵守语言要求，原文标题和引句按源规则保留 |
| 子代理只读分配批次 | 批次代理；本批次证据及适用规则 | 只能取得自身批次，合并与正式提交由主执行者完成 |
| 按证据作评分 | 评分节点；规范化原文、rubric、允许编辑字段 | 模型形成判断，脚本保留锁定项并校验提交 |
| 可经正式提交修正 | 源指定的执行者；当前结果及修正依据 | 发现不合规内容后仍能走源允许的提交和重渲染路径 |

摘要节点的局部指令可描述“根据这些原文证据和大纲，按指定语言生成这些结构化槽位”，语言值与证据随输入提供。评分节点取得 rubric，引文代理取得本批次证据；这些局部输入与完整源包快照各有用途。

若 Skill 只规定自主调查目标，完整任务就是一个 agent 区段。将它强拆为固定检索和总结阶段，可能改变源允许的调查顺序。

## 文件和资源

若源要求 `report.csv`，框架返回一个说明字符串不算生成文件。该文件的路径、编码、列和覆写政策来自源契约和任务上下文；与之不同，模板路径指向携带的 `source/<源包名>/`。

源脚本可能按参数选取 `templates/` 中不同文件。当前场景只用一份，不代表其他文件无用。对于要求评分时才读取的 rubric，可提供作用域限定的读取工具，在评分阶段使用，避免将整包资料预先注入每个节点。

## 暂停和恢复

在“确认后写入”的源流程中，确认节点形成问题并调用 `interrupt()`，批准分支连接写入节点。相同 thread 标识下的 `Command(resume=回复)` 继续该流程。内存检查点能演示进程内恢复，但不能证明崩溃后的外部写入安全；外部服务提供的幂等键可为相应操作提供更强保障。

## 自主性和权限

源要求“直到足够支持结论”时，模型依据输入、上下文和工具结果决定是否继续。固定三次检索会使“证据不足但已检索三次”的场景错误结束；运行步数上限触发对应的是执行受限。

若平台字段中的工具清单仅规定免确认范围，未列出的工具仍可能在授权后使用。例如读取已预授权、发布需确认时，仅注册读取工具就会丢失发布能力；把发布也当作预授权则会丢失确认边界。

## 保真复核例子

两个图可能输出相同报告，但一个在确认前已写文件；后者违背源。即便图拓扑相同，充分性判断也可能被改成固定次数。只观察最终内容或图形，无法判定这些义务；未触发的分支也仍缺少运行证据。

引文 JSON 的 language 标成中文，而 summary 和报告正文仍为英文，是语言违约。检查主键覆盖和渲染一致性都无法判断这一点。可分别核对代理实际收到的语言值、批次权限、最终正文及正式修正后的产物；保留初次提交，才能分清修正和首次成功。
