# Skill 转为 LangGraph

## 目标与非目标

将源 Skill 的指令、资源和能力调用转换为可执行的 Python LangGraph 应用，用图表达固定控制，保留源允许的模型判断空间。
保留源的目标、非目标、顺序、权限、确认、失败策略和输入输出契约。

本 Skill 不负责修改源任务、递归转换所有被调用的 Skill，或为任意环境配齐模型、工具与服务。
运行环境提供模型、工具、委派接口、凭据、交互界面和所需存储；图负责声明依赖并实现调用逻辑。

## 输入、输出与保真边界

必需输入只有源 Skill 包路径。输出目录可选，默认任务当前目录的 `<skill-name>-graph/`。
从合法自足的包开始转换；运行记录、模型凭据和服务接入不是开始转换的前提。

交付一个 Python LangGraph 应用，包含完整源包快照、实际图代码、`langgraph.json`、依赖声明和运行说明。
应用同时支持 Python 和 `langgraph` CLI，二者共享图逻辑。
源业务输入输出与图框架的调用封装分别描述，提供无损映射。
源要求的文件、文件格式、工作目录语义和副作用仍须实际产生。

按源规定判断输出相等性；源未固定措辞时核对内容与行为，不要求逐字一致。
当前环境缺少外部能力时，继续生成已可确定的调用逻辑，在验证与交付时列明缺口。

## LLM 与脚本职责

| 执行者 | 职责 |
| --- | --- |
| 转换 Agent（LLM） | 理解源契约与冲突，选择图结构，生成代码与局部指令，复核语义保真并汇总证据 |
| `scripts/skill_package.py` | `inspect` 只读校验及盘点源包；`copy` 在新目录完整复制源包 |
| `scripts/check_graph.py` | 检查生成 Python 语法、配置及可静态确定的入口和显式资源路径 |

按执行流程调用这三个操作；结果字段与失败处理见末节。脚本不承担语义路由或保真判断，生成代码与局部指令由 Agent 完成。

## 禁止事项

- **不得为提高可控性擅自增加、删除或修改源业务行为、审批、重试、降级或补偿。**
- **不得改写源包、裁剪源快照或覆盖已有输出来迁就转换；使用第 4 步的新目录策略。**
- **不得以空函数冒充能力实现，或将静态通过、替身结果及未接入能力声称为真实整体执行或保真通过。**

## 执行次序

### 1. 检查源包

定位本 Skill 包根目录，以其绝对路径调用下列辅助脚本；命令中的 `python` 代表调用环境提供的 Python 3.11+ 解释器。
遵守当前环境的依赖和写入授权，不自动安装依赖。

```sh
python "<本Skill根>/scripts/skill_package.py" inspect "<源包路径>"
```

此操作只读。检查 `ok`、退出码及问题路径，读取源根 `SKILL.md` 和盘点到的包内资源。
目录名不决定资源语义；跟随正文引用，包含自定义目录和动态选取资源。
先读核心指令，按原读取条件理解补充资料，保留渐进式披露。
额外平台元数据原样保留，结合相应平台语义解释。

源包格式不合规、读入失败时，指出定位信息并按末节处理。
发现会改变行为的真实矛盾时，列出文件位置、冲突解释及各自影响，请求澄清后继续相关部分。
普通定性要求或模型自主判断不构成缺材料；保留其自由度。

完成条件：取得完整盘点，能区分源指令、脚本、资源及外部依赖，并已定位阻塞转换的真实冲突。

### 2. 提取源契约

形成简短的源契约与映射工作表，以文件位置为依据，至少覆盖：

- 触发方式和平台字段含义，业务输入、会话上下文、工作目录及输出。
- 固定阶段、分支、循环停止条件、源许可的并行和自主区段。
- 文件、外部副作用、权限、确认点、失败和恢复要求。
- 资源的读取条件、脚本调用方法、模型要求及工具和委派依赖。

每条源约束记录源位置、执行者、所需输入、实现位置和验证方法；同一义务在多个执行者处适用时，列出各自接收点。
将固定控制、确定性工作、语义判断、权限和资源读取条件分别分配给适当职责；未使用的资源仍保留在快照中。
对平台特有能力记录实际调用约定，区分工具存在、预授权和禁止规则。
`allowed-tools` 按适用平台解释，不能一律视为仅准许注册这些工具的白名单。
调用其他 Skill 或 agent 时记录调用关系、调用约定和依赖。

形成映射时读 [映射示例](references/skill-to-langgraph-mapping.md)，用于选择局部结构和检查容易丢失的语义。
完成条件：源可观察行为、能力和资源的去向均有依据；环境缺口与源材料问题分开记录。

### 3. 选择图结构与调用契约

**结构与局部职责。** 按局部语义选择结构，允许同一图内组合：

- 固定流程及外部可观察的阶段约束用 `StateGraph` 节点和边表达。
- 自主区段在能保持源约束时用 `langchain.agents.create_agent`。
- 混合流程用固定阶段约束连接自主区段；纯自主流程可直接导出 agent 图。

节点按职责、数据传递、暂停或副作用边界划分，不能按句子或编号机械拆分。
有工具调用不意味着需要手写模型循环。
明确数据条件用代码判断；证据充分性、质量等语义条件交给模型，保留相应分支。

在转换时理解完整源流程并完成职责拆分。固定顺序、分支和停止条件落实在图中；运行 agent 只执行分配给它的自主区段。
为每个自主区段生成局部指令，包含任务目标、适用源约束、可用能力、输入输出及返回条件。多阶段图不得默认在每个阶段重新注入完整源 Skill，让模型重复解释全流程。
完整任务确属一个不可独立固定阶段的自主区段时，保留其所需完整指令与判断空间；局部拆分不能改变源自主性。

**状态与上下文。** 状态只保存跨阶段传递、会话和恢复所需内容，不强制统一 `messages/artifacts` 模型。
节点返回局部状态更新；默认覆盖通道，需要聚合时再选择 reducer，并行写入时核对其是否保持源语义。
在消费点明确提供业务参数、适用约束和必要历史上下文；值从源规定的真源取得，不能只告诉模型遵循它无法读取的配置。
节点调用 agent 时传递适用的运行配置并映射所需状态；嵌套图需要恢复时，核对检查点传播与调用命名空间。
委派时传递子任务适用的约束及必要参数，并维持源规定的证据、批次及工具权限边界。主 agent 的上下文不会自动成为子 agent 的上下文。

**控制与恢复。** 并行须有源许可；逐项措辞不自动授权并行，保持项目对应关系、顺序及副作用时机。
源循环按源停止条件和明确次数限制结束；运行时步数上限触发应报告执行受限。
使用 `Command(goto=...)` 时避免与静态边重复调度同一后续任务。

确认点用实际暂停与恢复实现；环境负责呈现问题、提交回复并保留会话标识及存储，恢复沿用对应会话与检查点。
内存检查点仅支持存活进程内恢复；跨进程恢复按声明接入环境提供的持久化设施。`store` 用于跨会话数据，与检查点分工不同。
暂停节点恢复可能从头执行，副作用安排在不会因该暂停重跑而重复的位置。
检查点不能单独保证任意故障下的 exactly-once；使用确实有效的幂等支持或明确恢复限制。
将模型技术重试设置与源失败策略一起核对，不能以图级重试替代失败停止。
为源允许的修正、重新提交、重渲染和恢复保留可达路径，并明确由谁判断和发起。
阶段推进和首次提交成功不能单独成为封闭这些路径的理由；修正仍受源的写入权限、失败策略及副作用条件约束，不扩展成自动重试或补偿。

**能力接入。** 模型有源要求时保留；否则由运行配置显式提供，避免隐式绑定供应商，声明所选供应商集成包。
能力适配器实现真实调用路径、输入输出和失败语义。
凭据从环境取得，不写入代码或复制会话配置。

生成具体代码之前读 [运行 API](references/runtime-api.md)，按所用 LangGraph、LangChain 和 CLI 版本核对图、agent、暂停和入口机制；资料提供 API 示例与易错机制的说明。
完成条件：结构和调用封装都能解释源行为，依赖与权限前提已明确。

### 4. 创建独立应用并生成图

```sh
python "<本Skill根>/scripts/skill_package.py" copy "<源包路径>" [--output "<新目录>"]
```

先确认输出路径；已有目标或源目标重叠时请求另选新目录，不能覆盖重试。
复制成功后，在返回的 `output_dir` 中生成代码；`source_dir` 是完整源包快照。
复制会保留文件内容、相对布局及执行所需属性；符号链接内容被实体化，使资源可搬移。
复制失败可能留下部分新产物，报告位置和问题，不自动清理用户文件。

推荐布局：

```text
<skill-name>-graph/
  source/<original-package-name>/...
  skill_graph/
    __init__.py
    graph.py
  langgraph.json
  pyproject.toml
  README.md
```

完整源包与新增代码分放。
源快照用于按需调用资源和追溯；局部运行指令按职责生成，不以携带完整快照代替约束落实。
保留源名称，graph ID 在目标允许时沿用源名；Python 技术标识使用合法名称，并在说明中记录必要映射。
资源相对搬移后的模块或应用根定位，不能依赖原包绝对路径。
源指定的业务工作文件仍按任务工作目录处理，与随应用携带的资源区分。
源脚本按原解释器、参数、工作目录、权限和失败要求调用。

只维护一份图装配逻辑。根据需要导出编译图或工厂，`langgraph.json` 指向真实入口。
配置引用的本地文件随应用携带，密钥仍从环境取得。
Python 接口按需接入检查点和 store，服务入口采用服务提供的设施，不硬编码存储后端。
服务工厂按目标 CLI 支持的完整签名接收配置，核对可选及 keyword-only 参数是否也计入参数数目；需要时以薄入口转调同一装配函数，不依赖服务内部 API。
无需强制同时导出图对象和工厂；不要将 `src` 当作通用导入前缀。
`pyproject.toml` 声明依赖与可安装代码，包含运行所需资源的分发安排。
若支持 wheel 安装，实际检查包内资源包含和定位；只支持应用目录运行时明确说明该部署形态。

README 写明：

- 源契约到 Python/CLI 的具体调用映射及输出提取方法。
- 依赖、工具和委派接入方式、权限前提、显式模型配置及凭据环境变量。
- Python 调用、`langgraph` CLI 配置和调用、适用的暂停/恢复方法。
- 资源定位、部署形态、故障恢复限制和尚未取得的运行证据。

仓库测试环境和开发议题不属于发布包或生成图依赖。
完成条件：新应用能独立说明自身输入输出、入口、资源、能力调用和配置前提。

### 5. 检查并验证

```sh
python "<本Skill根>/scripts/check_graph.py" "<生成目录>"
```

此操作检查生成 Python 语法（跳过源快照）、JSON 配置和可确定的本地入口与显式资源路径；无法静态定位的外部入口列入 `unresolved_entries`，仍须取得加载证据。
它不导入模块、不调用模型或服务、不判断自然语言保真；修复其报告的生成问题后再检查。

按当前授权与环境执行可行验证，记录命令、配置标识、观察结果和覆盖范围：

1. 核对完整快照、名称映射、依赖声明和源契约工作表。
2. 有运行条件时，实际加载和调用图，检查用户可观察行为、文件、副作用和失败。
3. 声称 Python 与 CLI 可执行时，为两种入口分别取得加载与基本调用证据；一条入口可承担深入业务验证。
4. 存在暂停时核对回复恢复和副作用时机；有搬移承诺时在新目录实际读取携带资源。
5. 按契约工作表核对跨节点、委派及恢复时的输入和规则可见性；源允许的修正路径取得实际调用证据。

验收以源契约为判据；源与图都产生同样结果也可能都违约。
替身只证明所覆盖的边界，不能代替真实模型和工具的整体行为证据。
语义结果按源要求复核，不以字数、关键词或拓扑一致代替业务判断。
核对正文是否满足语言、内容依据和证据范围；配置标签、结构合法及产物齐全不能代替这项复核。
复验使用独立生成和运行目录，保留此前产物及失败依据；重新转换的证据与仅修补既有图的证据分别说明。
外部依赖缺失时保留可生成产物，列出具体受阻验证；未运行、证据不足和环境受阻不计通过。
图逻辑失败与运行条件缺口分开报告。默认不要求 Docker 或托管部署验收。

### 6. 交付结果

交付应用位置、入口、源业务调用映射和运行条件。
逐项区分确定性检查、真实执行、替身验证、未运行及受阻内容。
有已知源约束违约时继续修复或明确阻塞，不能宣称保真完成。
转换代码生成完毕与全部验收通过分别陈述。
完成条件：交付位置、调用映射、运行前提及证据范围均明确，已知违约已修复或如实列为阻塞。

## 辅助命令结果与失败处理

两个脚本均支持 `--help`，普通文本输出，退出 0，无写入。
其他受控调用输出一个 JSON 对象：

```json
{"ok": true, "operation": "inspect", "data": {}, "issues": []}
```

`operation` 为 `inspect`、`copy`、`check`；包处理命令无法识别操作时为 `null`。
`data` 总为对象，失败可为空；`issues` 总为数组，每项为 `code`、`path`、`detail`，无相关路径时 `path` 为 `null`。
根据退出码、`ok` 和问题码处理结果，不解析完整提示文案。

| 操作 | 成功的 data |
| --- | --- |
| inspect | source_root、metadata、按包内相对路径排列的 files（path、type） |
| copy | output_dir、source_dir |
| check | checked_files、graph_entries，以及无法静态定位的 unresolved_entries |

| 退出码 | 问题码 | 处理 |
| --- | --- | --- |
| 0 | 无 | 该次确定性操作完成，继续下一步 |
| 2 | invalid-argument | 校正参数；依赖缺失时先提供已获授权的解释器环境 |
| 3 | invalid-source | 定位源包格式问题并请求修正或澄清 |
| 4 | output-conflict | 请求新的输出位置 |
| 5 | io-error | 报告读写位置、原因及可能留下的部分产物 |
| 6 | invalid-artifact | 修复生成代码或配置后重查 |

`_cli.py` 是两个命令的内部结果协议模块，与脚本一起携带，不单独调用。
